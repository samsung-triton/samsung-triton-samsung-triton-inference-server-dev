# 📘 Triton 관제 시스템 포팅 매뉴얼

# 1. GitLab 소스 클론 후 빌드 및 배포를 위한 설정 문서

## 1-1. 공통 환경

다음 환경에서 정상 동작합니다.

* **운영체제:** Ubuntu 20.04 이상
* **필수 설치 프로그램**

  * Git
  * Docker / Docker Compose (선택)
  * Python 3.11 이상 (Backend)
  * Flutter SDK (Frontend)
  * Chrome 브라우저 (Flutter Web 실행용)

---

# 2. Backend(FastAPI) 포팅 매뉴얼

## 2-1. 주요 파일 구조

```
Backend/
 ├─ main.py                      # FastAPI 실행 진입점
 ├─ requirements.txt             # Python 패키지 목록
 ├─ Dockerfile
 ├─ app/
 │   ├─ api/v1/                  # REST API 라우터
 │   ├─ core/
 │   │   ├─ config.py            # 환경변수 Settings 관리
 │   │   ├─ DB/
 │   │   │   ├─ database.py      # PostgreSQL 연결
 │   │   │   └─ clickhouse.py    # ClickHouse 연결
 │   ├─ models/                  # SQLAlchemy 모델
 │   ├─ schemas/                 # Pydantic 스키마
 │   ├─ services/                # 비즈니스 로직
```

---

## 2-2. 환경 변수(.env) 설정

Backend 루트에 `.env` 파일을 생성한 뒤 아래 내용을 채워 넣습니다.

```
APP_NAME=TritonDashboard
APP_ENV=prod
DEBUG=false
LOG_LEVEL=INFO
BIND_HOST=0.0.0.0
BIND_PORT=8080
MAX_WORKERS=4

# PostgreSQL
DB_HOST=<POSTGRES_HOST>
DB_PORT=<PORT>
DB_NAME=<DB_NAME>
DB_USER=<USER>
DB_PASSWORD=<PASSWORD>

# ClickHouse (선택)
CHK_HOST=<HOST>
CHK_PORT=<PORT>
CHK_DB=<DB_NAME>
CHK_USER=<USER>
CHK_PASSWORD=<PASSWORD>

# Triton / Prometheus 연동
TRITON_GRPC_URL=grpc://<TRITON_IP>:8001
TRITON_MODEL_REPO=/models/repository
TRITON_COMPOSE_PATH=/path/to/docker-compose.yml
TRITON_CONTAINER_NAME=triton_server
PROM_URL=http://<PROMETHEUS_IP>:9090

# 기타 설정
INFER_DATA_SAVE_PATH=/data/inference
ALLOW_OVERWRITE=false
TIMEZONE=Asia/Seoul
```

---

## 2-3. 로컬 실행 절차

### 1) 프로젝트 클론

```
git clone <Backend GitLab URL>
cd Backend
```

### 2) 가상환경 생성 및 활성화

```
python -m venv venv
source venv/bin/activate
```

### 3) 패키지 설치

```
pip install -r requirements.txt
```

### 4) DB 덤프 복원 (섹션 4 참고)

### 5) 서버 실행

```
uvicorn main:app --host 0.0.0.0 --port 8080
```

### 실행 후 확인 사항

* PostgreSQL 연결 성공 로그
* ClickHouse 연결 성공 로그
* Triton 서버 gRPC 연결 성공 여부

---

## 2-4. Docker 기반 배포

### 1) 이미지 빌드

```
docker build -t triton-backend .
```

### 2) 컨테이너 실행

```
docker run -d \
  -p 8080:8080 \
  --env-file .env \
  --name triton-backend \
  triton-backend
```

### 주의사항

* `TRITON_GRPC_URL`은 Triton gRPC 포트(기본 8001)와 정확히 일치해야 합니다.
* Prometheus 및 DB는 백엔드보다 먼저 실행되어 있어야 정상적인 메트릭 조회가 가능합니다.

# 3. Frontend(Flutter Web) 포팅 매뉴얼

## 3-1. 주요 파일 구조

```
Frontend/
 ├─ triton/
 │   ├─ lib/
 │   │   ├─ main.dart            # 앱 진입점
 │   │   ├─ router.dart          # 라우팅 설정
 │   │   ├─ controller/          # GetX 컨트롤러
 │   │   ├─ screen/              # 화면 UI
 │   │   ├─ widgets/             # 공통 컴포넌트
 │   │   ├─ theme/               # 색상 및 타이포그래피
 │   ├─ pubspec.yaml             # 패키지 의존성
 │   ├─ build.zip                # 웹 빌드 결과물
```

---

## 3-2. 개발 실행 방법

```
cd Frontend/triton
flutter pub get
flutter run -d chrome --web-port 3000
```

접속 주소:

```
http://localhost:3000/#/login
```

---

## 3-3. 릴리즈 빌드

```
flutter build web --release
```

빌드 결과물 경로:

```
build/web
```

---

## 3-4. 운영 시 주의사항

* Flutter Web은 **Hash Routing(`/#/`) 구조**이므로 서버에서 추가 리다이렉션 설정이 필요 없습니다.
* API 주소 변경 시 `api_client.dart` 내 base URL 수정 후 다시 빌드해야 합니다.
* 정적 파일만 배포하면 되므로 Nginx, Apache, S3 등 어떤 스토리지에서도 제공할 수 있습니다.

# 4. DB 접속 및 ERD 관련 문서

## 4-1. 사용 DB 종류

* **PostgreSQL**
  사용자, 모델, 버전, config, 서버 이력, 추론 메타데이터 저장
* **ClickHouse**
  대량 추론 로그 및 시계열 메트릭 저장(선택)

---

## 4-2. 주요 모델 파일

| 모델 파일                      | 주요 테이블                 | 설명                 |
| -------------------------- | ---------------------- | ------------------ |
| `models/user.py`           | users                  | 로그인 계정 및 권한        |
| `models/model.py`          | models, model_versions | 모델 및 버전 정보         |
| `models/model_config.py`   | model_configs          | config.pbtxt 버전 관리 |
| `models/server.py`         | server_logs            | 서버 제어 이력           |
| `models/inference_logs.py` | inference_logs         | 추론 로그              |

---

## 4-3. DB 설정 관련 파일

* app/core/DB/database.py
* app/core/DB/clickhouse.py
* 위 파일들은 `.env`의 DB 환경 변수를 자동으로 로드함

# 5. DB 덤프 파일 최신본

## 5-1. 제출해야 할 덤프 파일

```
exec/db/postgres_dump.sql
exec/db/clickhouse_dump.sql (선택)
```

---

## 5-2. 덤프 복원 방법

### PostgreSQL 복원

```
psql -h <HOST> -U <USER> -d <DB_NAME> -f exec/db/postgres_dump.sql
```

### ClickHouse 복원

```
clickhouse-client --host <HOST> --query="SOURCE exec/db/clickhouse_dump.sql"
```

# 6. 시연 시나리오

1. 사이트 접속 → 로그인

    * 운용자 로그인
        * ID: oper, PW: 1234
    * 개발자 로그인
        * ID: devel, PW: 1234
        
2. Dashboard 페이지 진입
    * 서버 GPU/CPU 리소스 그래프 확인
        * 기본 선택인 Triton 서버 확인
    * 실기간 업데이트 가능
        * 대시보드 화면 오른쪽 상단 업데이트 버튼 클릭
    * 모델별 추론 통계 및 지연 시간 확인
        * 오른쪽 사이드 바에 모델 카드 클릭
    * 최근 Notification 확인
        * 모델 선택 후 오른쪽 Notification 확인

3. Model Manage
    * 모델 항목 클릭 → 상세 정보 노출
    * 모델 등록
        * 모델 카드 사이드 바 아리 등록 카드 클릭
        * 모달에 알맞는 데이터 입력 후 등록
    * 모델 삭제
        * 삭제하려는 모델 카드 위에 있는 휴지통 클릭
        * 삭제 이유 입력
    * 버전 등록
        * 오른쪽 스크린 버전 테이블 위쪽에 있는 register 버튼 클릭
        * 모달에 알맞는 데이터 입력 후 등록
            * 파일은 부분은 하나 이상 등록
    * 버전 삭제
        * 삭제하려는 버전을 테이블에서 클릭
        * 삭제 이유 입력
    * 버전 테이블 아래 config.pbtxt 에디터 내용 수정 및 저장
        * config 설정에 에러가 나면 롤백이 되기에 적절한 수정 (문제가 있는 경우 변경없이 그대로 저장만 테스트)
        * 에디터 위에 save 클릭
        * 롤백 목록이 열리면 추가 되었는지 확인
    * 이전 버전으로 롤백
        * 롤백 리스트 모달에서 돌아가고 싶은 버전을 클릭
        * 롤백 리스트 모달 아래 get을 클릭
        * 에디터에 값을 확인 가능 (서버에서 롤백이 되는 것은 아니고 값만 에디터에 불러옴)

4. Triton Log
    * Triton Log 모델 선택
        * 화면 왼쪽 상단 드롭 다운을 이용해 로그를 확인하려는 모델 클릭
    * 필터링 테스트
        * 화면 오른쪽 상단 filter를 클릭
        * 여러 필터링 테스트


5. Server Log
    * 필터링 테스트
        * 화면 오른쪽 상단 filter를 클릭
        * 여러 필터링 테스트
